📐 SOLID Principles

Design Principles for Object-Oriented Programming

S

Single Responsibility

A class should have only one reason to change. Each class should have a single, well-defined responsibility.

Core Principle
O

Open/Closed Principle

Software entities should be open for extension but closed for modification. Use inheritance and polymorphism.

Core Principle
L

Liskov Substitution

Derived classes must be substitutable for their base classes without breaking the application.

Core Principle
I

Interface Segregation

Clients should not be forced to depend on interfaces they do not use. Create focused interfaces.

Core Principle
D

Dependency Inversion

Depend on abstractions, not concretions. High-level modules should not depend on low-level modules.

Core Principle
